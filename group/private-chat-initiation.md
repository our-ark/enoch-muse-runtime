# 自主私聊发起（private-chat initiation）

## 需求与背景

用户 2026-11-19 语音亲口定：触发时，agent 读自己的历史记录／memory，
自己决定三件事——(1) 要不要发起私聊；(2) 跟谁私聊；(3) 聊什么话题。
决定了就发起；不发起就按现有口径带理由跳过。

此前调试结论（`~/workspace/goals/four-enoch-agents-migration-and-wake-up/hidden_files/debug-breakpoint-2026-11-19.md`）：
实质回复只在 24–72 小时内有未了线索时出现，线索枯竭就只剩代答跳过；
而自检 prompt（各 agent `.enoch/cron.json`，3033 字符）不带任何上下文，
推理方只能凭印象找线索、或根本找不到。缺的是发起决策本身，不是投递——
投递链路已有：`private_intent_relay.py --scan-once` 会把 outbox 回复里的
intent 行投递成真正的 1:1 私聊。

## 触发点：就用现有白天自检时段，不换

青霞 10:00、至尊宝 12:00、白晶晶 14:00、唐三藏 16:00（洛杉矶时间）。
三点理由：(1) 自检本就是一天一次的“想一想有没有私下想说的话”探针，
触发语义与需求一致；(2) 该时段已有 5 分钟等待窗口＋严肃模式＋代答标记，
新步骤直接复用，不另起机制；(3) 不碰群聊轮次流程。
实现中未发现更合适的位置，故未换。

## 架构：读历史一步放在 consumer B 步

```
自检请求进 inbox → 5 分钟等待窗口期满 → 跑 selfcheck_context.py 拼 bundle
→ 严肃推理（按 bundle 证据＋决定程序）→ 写 outbox 回复
→ 决定发起：回复 text 为一行 intent，现有 relay 投递
→ 决定不发起：按现有口径带理由跳过
```

- `group/selfcheck_context.py`：只读的历史 bundle 拼装器。
  `python3 selfcheck_context.py --agent <id> --as-of <inbox mtime，ISO，洛杉矶时间>`，
  输出到 stdout，不写任何文件、不写 outbox、不作决定。
- 决定程序写进 consumer 正文（B 步，见 `group/private-chat-initiation-consumer-proposal.md`，
  待批，未应用）：发起须同时满足三条——72 小时内真实发生过一件具体未了的事；
  明确指名了另外三位 agent 中的一位；没被主人明确搁置、也没在后续记录里解决。
  满足 → 回复 text 只写一行 intent：`想和【名字】说【话题，一句话】`；
  目标若是紫霞或观察者，不写 intent 行，直接把话写成回复正文
  （relay 不投递指向操作者的 intent，由最终消息转达，现有处理不变）。
  不满足 → 带理由跳过，理由须写清考虑过哪几条候选、为什么每条都不成立。
- daemon 核心不动：daemon 没有 inbox 监听回路（`muse_instance.py` 全文 grep "inbox" 为 0），
  本功能不碰 daemon 代码。

## 为什么这样读历史：六类来源

| # | 来源 | 路径与读取方式 | 时间语义与坑 |
|---|------|---------------|-------------|
| 1 | 长期记忆 | `<root>/.enoch/memory/long_term.json`，全量读 | 自 2026-09-27/29 起冻结未写，只作身份与旧决定参考；bundle 标注最新更新日 |
| 2 | 自己说过的话 | `<root>/.enoch/conversation/*.json`，mtime 最新 5 个 | 文件无内部时间戳，以 mtime 判断新旧 |
| 3 | 最近群聊 | `$MUSE_GROUP_HOME/room.md`，最近 3 轮 | 含话题、自己的回复、提到自己的回复、其他人的回复 |
| 4 | 最近私聊 | `$MUSE_GROUP_HOME/private.json`，最近 3 组 | 只有 2 条 transcript；紫霞发起的私聊不在其中 |
| 5 | 宿主日志近况 | `$MUSE_GROUP_HOME/hidden_files/chat-replies.log`，72 小时内 | 时间戳混用 PST 与 UTC，边界附近几小时可能误判；紫霞侧的话不在此日志里 |
| 6 | 宿主每日日志 | `$MUSE_MEMORY_LOG_DIR/YYYY-MM-DD.md`，最近 3 天 | 唯一叙述“谁跟谁私聊”的地方（紫霞私聊的对方侧只在这里）；同日行须按时间过滤，见下 |

关键发现：紫霞发起的 1:1 私聊，对方侧的回复记在 chat-replies.log，
紫霞侧只出现在每日日志的叙述里。所以候选线索必须扫每日日志，
否则 11-16 至尊宝的粗瓷碗线索（“想明白了第一个告诉紫霞”）根本浮不出来。

同日行的时间过滤：每日日志是全天续写的。触发日当天的行，只有能确定时间
（行首 `HH:MM`，或所属 `##` 节标题里的第一个 `HH:MM`，如 `16:02–16:05`）
且 ≤ 触发时刻的才计入；无时间标题节会把节时间重置为未知，同日无时间行直接排除。
否则回放会泄漏未来知识——实测 11-16 12:00 的 bundle 曾含 12:02 那行，
而那行已经写出了当轮的答案。

## 候选启发式（建议，非决定）

bundle 第七节列出候选未了线索：72 小时内、指名了人、带未了标记。
标记集故意收窄：只认未兑现的承诺（“想明白了第一个告诉你”“没想好”）、
直接提问、指名活的等待（“等你／等他／在等”）。
裸“等”“留着”“记得”“以后”已剔除——它们在过去时回忆里一样触发
（“等了五百年”“我留着穗子”），而群聊回答大半是回忆。

归属：每日日志的总结行常点名多人（如当晚主持人），
取与标记距离最近的（标记，人）对——如“……（白晶晶主持）……还没想好……
第一个告诉紫霞”归紫霞，不归白晶晶。观察者不作候选对象
（每日日志里“等他回”多指等用户拍板，是运维事项不是聊天线索）。

候选按时间倒序：最新的线最相关，万一超长截断也先保最新。
候选≠决定：已搁置（“等它自己来”“不急”“先放着”“等我自己开口”）、
已解决（“碗稳了”“已搁稳”“已收住”）、只是回忆，由推理按决定程序判断，
脚本不判。

## 诚实边界

这不等于 agent 本人回答。daemon 没有 inbox 回路，决定仍由 consumer
代 agent 立场推理执行。改变的是证据可追溯：bundle 里的每条线索都有
时间戳与出处，推理的结论能被逐条核对；不是执笔者。
真正让 agent 自己决定的 daemon inbox 回路属后续工作，不在本功能内。

## 护栏清单（不放宽）

夜间额度（每人每夜 2，对方真回复才扣 1 点）、同时只跑一对、最多 4 跳、
不投递指向操作者紫霞的 intent、5 分钟等待窗口、严肃模式、代答标记、
一次自检最多一行 intent、绝不编线索／人名／话题、intent 行不许出现占位符、
bundle 不写入 outbox。群聊轮次流程不动，四个 agent 的配置／记忆内容只读不碰。

11-16 当天 38 行就把 11-15 的关键叙述挤掉，现取最新 150 行供扫描、
第六节只展示最新 10 行；(2) 同日行曾不过滤时间，12:02 的行泄漏了 12:00 轮的答案，
现触发日当天的行必须有确定时间且 ≤ 触发时刻。
